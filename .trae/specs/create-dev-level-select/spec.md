# 开发者关卡选择场景 Spec

## Why
开发过程中需要快速测试各个关卡，但现有系统要求按顺序解锁（前一个关卡完成后才能进入下一个关卡）。每次测试新关卡都需要手动解锁或修改保存数据，效率低下。

## What Changes
- 新增一个开发者专用的关卡选择场景 `test_level_select_all_unlocked.tscn` 及其脚本
- 该场景显示所有关卡，全部处于解锁状态，允许直接进入任意关卡进行测试
- 场景放置在 `tests/` 目录下，遵循项目的测试文件约定

## Impact
- 受影响的规范：无新增规范，复用现有 LevelManager 和关卡选择 UI 模式
- 受影响的代码：新增 2 个文件（测试场景 + 脚本），不修改现有代码

## ADDED Requirements

### Requirement: 开发者关卡选择场景
系统 SHALL 提供一个开发者专用的关卡选择场景，绕过关卡解锁限制，允许直接进入任意关卡进行测试。

#### Scenario: 显示全部解锁的关卡列表
- **WHEN** 开发者打开 `test_level_select_all_unlocked.tscn` 场景
- **THEN** 所有关卡卡片显示为解锁状态，无锁定变灰效果
- **AND** 每个关卡的"Play"按钮均为可点击状态

#### Scenario: 直接进入任意关卡
- **WHEN** 开发者点击任意关卡的"Play"按钮
- **THEN** 游戏直接加载该关卡，无需检查前序关卡是否完成

#### Scenario: 显示关卡元信息
- **WHEN** 场景渲染关卡卡片时
- **THEN** 每个卡片显示：缩略图（如有）、标题、副标题、计时模式、最佳时间（如有）

#### Scenario: 返回主菜单
- **WHEN** 开发者点击"Back"按钮或按 ESC 键
- **THEN** 返回主菜单场景

#### Scenario: 保持独立于正式关卡选择
- **WHEN** 开发者使用此测试场景时
- **THEN** 不影响 `level_select.tscn` 的正常功能
- **AND** 不修改任何保存数据或关卡解锁状态
